a calendly bot that brings the booking details to the call

know why someone booked before you ask them to explain it again. a calendly bot can read today's bookings and pull the details each invitee gave you.

by the dusk bot team · checked 20 november 2026 · how we made this

get a call brief in dusk chat, see who's still on the group roster, or ask which openings calendly actually offers for a particular appointment type.

what a bot can do in Calendly

start from the appointment, then read its invitees. an event type describes the service people book. a scheduled event is the actual appointment. each invitee has a separate record. that's where to look for the details behind a discovery call.

actiondusk bot treats it aswhat you would use it for
List scheduled eventsreadfind your active discovery calls inside today's time window
Get eventreadconfirm which booking matches a particular session
List event inviteesreadread the active roster for a group appointment
Get event inviteereadinspect one person's booking details before their call
List Event Typesreadidentify the appointment type for which you need openings
List event type available timesreadlook up bookable slots for that type in a short future window
List user busy timesreadsee busy intervals when diagnosing a gap in availability

composio, the connection service behind dusk bot's apps, lists 57 Calendly actions (version 20261120_00, read 20 november 20263). dusk bot treats 36 as reads, 2 as sends and 19 as changes.

only actions starting with a read word (get, list, search) count as reads, so a read-only bot can't call the rest. a send reaches people or moves money, like create share, and waits for your Allow unless you set a daily amount.

connect Calendly

  1. open Connected apps in the sidebar.
  2. pick Calendly and sign in on Calendly's own page, so your password goes to them and never to a bot.
  3. choose which bots may use it, and whether each may only read or may also change things. your bookkeeper doesn't need your Calendly.
  4. ask in plain words. reading and drafting happen freely; sending asks you first.

pick your host account and the event type you actually offer. connect calendly in dusk bot and give the bot reading access. tell it your time zone and what you call a discovery call. try a known booking and compare the invitee detail with the appointment you expected.

routines to copy

say which date and whose calendar matter. a group roster and a personal availability search answer different questions. set the event type and group session names in chat, then use the message that matches the job.

discovery call briefs

every weekday at 8, find my active discovery calls today. read each booking's invitee details. give me the call time, name and any reason they gave for booking. turn a missing answer into one opening question. keep unrelated contact details out of the brief.

weekdays at 08:00 · a short opening note for each discovery call

openings for a longer consult

at noon every monday, find available times for my long consultation event type over the next five days. show the earliest opening on each day in my time zone. mark days with no returned slots. leave the times open for booking.

mondays at 12:00 · bookable consultation times grouped by day

group clinic roster

each thursday at 3, find tomorrow's group clinic. list its active invitees. list cancellations separately so i can update my paper roster. keep repeat names separate unless their booking details match. if two clinics fit the name, show me the start times before picking one.

thursdays at 15:00 · a roster for the host to take into the clinic

what it asks you first

looking up a slot leaves it available to others. read-only access covers these three jobs. canceling a scheduled event changes the booking. it has no automatic send approval. leave cancellation off the action list for a prep bot.

what it cannot do

  • look up a month's open slots in one call. the event type availability action accepts a future window of at most seven days. split a longer search into shorter windows.
  • pull another host's organization bookings on ordinary personal access. use your own user scope for your schedule. organization-level member or group queries require an admin or owner.
  • promise a time will stay open. the lookup reads availability. it doesn't reserve a place for someone who might book later.

when to use the booking link

use the calendly link directly when someone just needs to choose a time. a list in chat ages as people book. the bot is more useful when the host needs to choose staffing, prepare questions or reconcile a roster before the session.

questions

can a busy-time lookup tell me which appointments are bookable?

use the event type's available times for that. a busy interval helps explain a gap. a stretch that looks empty doesn't tell you which appointments calendly offers there.

what goes in the brief when someone skips a booking question?

leave the answer blank and bring one question. keep wording from the invitee separate from your suggested opener so the host knows which came from the booking.
