what a bot can do in Google Docs

start with the source paragraph. a sentence is easier to fix when you know which document and tab it came from. use plain text for a first read and the document structure when headings or tabs matter.

composio, the connection service behind dusk bot's apps, lists 48 Google Docs actions (version 20261116_00, read 20 november 20263). dusk bot treats 8 as reads, 0 as sends and 40 as changes.

only actions starting with a read word (get, list, search) count as reads, so a read-only bot can't call the rest. a send reaches people or moves money, and waits for your Allow unless you set a daily amount.

connect Google Docs

  1. open Connected apps in the sidebar.
  2. pick Google Docs and sign in on Google Docs's own page, so your password goes to them and never to a bot.
  3. choose which bots may use it, and whether each may only read or may also change things. your bookkeeper doesn't need your Google Docs.
  4. ask in plain words. reading and drafting happen freely; sending asks you first.

give the bot the master and the working draft as separate links. label them in chat. connect google docs under connected apps and choose the bot that edits with you. try a read first. ask which tab contains the delivery promise and have it quote the line.

routines to copy

decide which document has the final say. paste the links into chat before starting a routine. tell the bot what you call each document so the instructions below refer to the right files.

weekly report from dated notes

every friday at 2, read this week's entries in <notes doc link>. draft the weekly report here under shipped, delayed and awaiting a decision. put the source heading beside each item. leave out undated notes unless i confirm the week.

fridays at 14:00 · a report you can trace to the original notes

proposal against the signed brief

on tuesdays at 10, compare the delivery dates and included revisions in <proposal link> with those in <signed brief link>. quote each conflicting pair here with its tab and heading. ask which wording wins. leave both files alone.

tuesdays at 10:00 · pairs of promises for the account owner to settle

template leftovers

each weekday at 4, read <proposal link> including its tables and footers. find bracketed instructions, sample client names and blank fee fields. quote the surrounding words here so i can find them. keep the master intact.

weekdays at 16:00 · a punch list for the last editorial pass

what it asks you first

decide where a draft can become an edit. a draft in chat leaves the document alone. copying the master and inserting text are writes. neither comes with a send approval. for hands-on editing, put “ask me before you change anything” in the routine and name the working copy.

what it cannot do

  • promise a clean replacement on the first try. the section update can insert new text while leaving the old passage. read the result before retrying.
  • preserve page layout in plain text. that action gives a best-effort rendering. open the actual document for a final layout review.
  • approve a disputed fee. if two sources disagree, the account owner needs both quotes. choosing a number requires their decision.

when to open the document yourself

do the final visual proof in google docs. a text review can find a missing fee. it can't tell you from plain text how a table breaks across pages. if your only job is lining up the signature block, skip the bot.

questions

where does a copy of my report template go?

the copy starts in the root of your google drive. give it a distinct title when you ask for it. use its link for subsequent edits.

can it review a draft without writing in it?

yes. give the bot read access to docs. ask for the exact sentence, the source heading and a proposed replacement in chat.
