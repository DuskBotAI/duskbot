sort a dropbox inbox without guessing where files belong

a file called scan.pdf could be a receipt, a contract or last week’s menu. give your bot two filename rules and let it sort only the files that fit.

by the dusk bot team · checked 20 november 2026 · how we made this

you see each source and destination in chat before you choose what moves. ambiguous names stay in the dropbox inbox.

the message

paste this into a chat with your bot

each friday at 3 pm, list every file directly inside /inbox in my work dropbox. read filenames only. skip subfolders. propose moving names starting with receipt- to /receipts and signed- to /signed. keep the filename. if neither prefix fits, leave the file for me.

show the full source and destination paths here. flag missing folders or existing destination names and skip those moves. ask me before you change anything. wait for me to choose specific rows. before moving each file, confirm it still matches the proposal and its destination is free. skip it if anything changed.

never overwrite, auto-rename, delete or share. report the moves that succeeded and any that failed. stay quiet if the complete inbox listing contains no files. report a listing error here.
when
fridays at 3 pm, with moves waiting for your choice in chat
needs
dropbox folder listing and metadata reads. allow the move action only if you want the bot to carry out your choices.3

what comes back

an example, not a real run

friday sort · proposed only
1. /inbox/receipt-faye-brooks.pdf → /receipts/receipt-faye-brooks.pdf
hold: /inbox/signed-lease.pdf already has a namesake in /signed.
leave for you: /inbox/scan.pdf has no matching prefix.
move row 1?

make it yours

  • start with a dry run. give dropbox read-only access. you can compare the paths and do the filing yourself.
  • match the names your scanner uses. choose a prefix you can apply consistently. a file extension alone says little about the contents.
  • narrow the inbox. point the routine at one client’s intake folder if several clients use the same naming convention.

when it goes wrong

  • the listing stops partway down the folder. continue through the remaining results before proposing the batch. a first page can miss files.3
  • you approved a file that someone has since renamed. skip that row. read the new name and ask for a fresh decision.

make a name collision a decision

two files with the same name can hold different agreements. leave both where they are until someone compares them. adding a suffix makes the move possible, but leaves the next reader guessing which copy to use.

if the only reliable filing clue is inside a scanned document, this filename routine is the wrong pick.

questions

does listing files require permission to move them?

read only works for the proposal. moving a chosen file needs the separate dropbox move action. keep the instruction to ask before each approved set of changes.

what if only part of the sort worked?

use the reported paths to locate each file. refresh the inbox and destination before retrying a failed row. leave successful moves alone.
